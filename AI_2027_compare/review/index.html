01 · 왜 이 실험을 했는가

“대단하다”는 말만 듣다가, 처음으로 직접 써봤습니다

이 글은 전문가의 벤치마크가 아니라, AI 에이전트를 처음 써본 사람의 솔직한 체험기입니다.

들어만 봤던 것

그동안 주변에서 “AI 에이전트가 대단하다”는 말은 정말 많이 들었습니다. 그런데 정작 제가 직접 써본 적은 없었어요. 머릿속으로 “알아서 일을 해주는 AI” 정도로만 이해하고 있었죠.

직접 해본 것

이번에 처음으로 여러 AI 에이전트를 직접 사용해봤습니다. 같은 자료를 주고 웹페이지를 만들어달라고 했더니, 몇 분 만에 세 도구가 각자 다른 웹페이지를 완성해냈습니다.

AI 에이전트란? 질문에 답만 하는 챗봇과 달리, 목표를 주면 스스로 계획을 세우고 파일을 만들고 고치는 등 실제 작업까지 수행하는 AI입니다. 이번 실험에서는 “웹페이지를 만들어줘”라는 말 한마디로 실제 실행 가능한 파일이 만들어졌습니다.

📄

같은 자료

미래 AI 시나리오 「AI 2027」에 관한 동일한 자료를 세 도구에 똑같이 제공했습니다.

💬

거의 같은 프롬프트

“이 자료로 일반인이 이해하기 쉬운 웹페이지를 만들어줘”라는 취지의 요청을 거의 그대로 사용했습니다.

🤖

세 가지 도구

Codex · Claude Code · Antigravity

참고해주세요 아래 점수와 순위는 한 번의 실험과 제 개인적인 사용 경험을 바탕으로 한 주관적인 평가입니다. 같은 도구라도 프롬프트나 상황에 따라 결과가 달라질 수 있습니다.
03 · 세 결과물 한눈에 보기

세 도구, 세 가지 성격

한 줄로 요약하면 이렇습니다.

Claude Code

종합 1위

“가장 잘 전달하는 결과물”

  • 현실과 가상의 구분이 가장 명확
  • AI 2027이 ‘미래 시나리오’임을 분명히 전달
  • 저자의 메시지가 일반인에게 잘 전달됨
  • 정보 구조와 가독성이 좋음
  • 미리보기·확인 과정이 가장 편함

Codex

가장 절제됨

“차분하고 깔끔한 편집자”

  • 과장된 표현이 적고 차분함
  • 정보 정리가 비교적 잘 됨
  • 모바일에서 무리 없이 보임
  • PC 큰 화면에선 디자인이 다소 헐거움
  • 미리보기·확인 흐름이 조금 덜 직관적

Antigravity

디자인 1위

“가장 웹사이트다운 첫인상”

  • 카드·메뉴·다크 테마 등 디자인 완성도 높음
  • 흥미와 몰입감이 강함
  • 표현이 드라마틱해 공포 시나리오처럼 읽힐 수 있음
  • 권한·승인 단계가 많아 사용 과정이 복잡
  • 나에게는 가장 어려웠던 도구

06 · 사용하면서 느낀 차이

결과물만큼 달랐던 건 ‘쓰는 과정’이었습니다

처음 쓰는 사람에게는 중간에 내가 무엇을 판단해야 하는지가 큰 차이로 다가왔습니다.

요청 입력작업 진행결과 미리보기·확인
Codex큰 차이 없이 무난

노란 단계 = 사용자가 직접 판단해야 했던 순간 (흐름을 단순화한 그림입니다)

Claude Code

결과물을 미리보고 확인하는 과정이 가장 자연스러웠습니다. “다 됐다 → 바로 확인”의 흐름이 끊기지 않아서, 처음 쓰는 저도 헤매지 않았습니다.

Codex

사용 난이도 자체는 Claude Code와 크게 다르지 않았습니다. 다만 만들어진 결과를 미리보고 확인하는 흐름이 조금 덜 직관적이었습니다.

Antigravity

권한 허용, 파일 처리, 변경사항 승인처럼 제가 판단해야 하는 단계가 가장 많았습니다. 무엇을 눌러야 할지 고민하는 순간이 잦아, 세 도구 중 가장 어렵게 느껴졌습니다.

💡
처음 쓰는 분께 드리는 팁 AI 에이전트가 “이 파일을 수정해도 될까요?”, “이 명령을 실행해도 될까요?”라고 묻는 건 안전을 위한 장치입니다. 귀찮게 느껴질 수 있지만, 무엇을 허락하는지 한 번씩 읽어보는 습관이 좋습니다.
07 · 클라우드 작업과 로컬 작업

비교 작업을 하다 보니, 컴퓨터가 일하는 ‘장소’가 보이기 시작했습니다

이번 실험의 숨은 수확은 GitHub, 로컬 작업, 클라우드 작업이 무엇이 다른지 몸으로 알게 된 것입니다.

💻

로컬 작업

내 컴퓨터 안에서 AI가 일합니다. 결과 파일이 내 폴더에 바로 생기고, 더블클릭으로 바로 열어볼 수 있습니다. 대신 내 컴퓨터의 파일을 건드리기 때문에 권한을 묻는 경우가 많습니다.

⇄
🗂️

GitHub

파일을 보관하고 변경 이력을 남기는 온라인 저장소입니다. 내 컴퓨터와 클라우드 사이에서 작업물을 주고받는 ‘공용 창고’ 역할을 합니다.

⇄
☁️

클라우드 작업

인터넷 너머의 다른 컴퓨터에서 AI가 일합니다. 내 컴퓨터를 켜두지 않아도 되지만, 결과물을 GitHub 등을 통해 받아와야 내 손에 들어옵니다.

“결과 파일이 어디에 생겼지?”를 몇 번 헤매고 나니,
‘어디서 일하느냐’에 따라 확인하는 방법이 달라진다는 걸 알게 되었습니다.

이전의 나

  • GitHub = 개발자들이 쓰는 어려운 사이트
  • 클라우드 = 그냥 인터넷 어딘가
  • AI 에이전트 = 똑똑한 챗봇

지금의 나

  • GitHub = 작업물을 보관·공유하는 창고
  • 로컬과 클라우드 = AI가 일하는 ‘장소’의 차이
  • AI 에이전트 = 실제로 파일을 만들고 고치는 동료
08 · 최종 순위

“누가 최고냐”보다, “무엇에서 최고냐”

하나의 순위로 줄 세우기보다, 각 도구가 빛난 지점을 나눠서 정리했습니다.

🏆
결과물 품질 1위
Claude Code

현실과 가상의 구분, 메시지 전달력, 가독성까지 일반인을 위한 페이지로 가장 완성도가 높았습니다.

🎨
디자인 첫인상 1위
Antigravity

처음 열었을 때 “와, 진짜 웹사이트 같다”는 느낌이 가장 강했습니다. 시각적 몰입감은 단연 최고.

🖋️
가장 절제된 편집 스타일
Codex

과장 없이 차분하게 정리한 톤. 공포감 없이 담담하게 내용을 전달하는 데는 가장 뛰어났습니다.

🔁
내가 다시 쓰기 가장 편한 도구
Claude Code

미리보기와 확인이 가장 편했고, 결과도 만족스러웠습니다. 다음에도 가장 먼저 손이 갈 도구입니다.

09 · 이번 실험을 통해 느낀 점

머리로 알던 것을, 처음으로 체감했습니다

같은 자료와 거의 같은 프롬프트를 넣었는데, 몇 분 만에 서로 다른 웹페이지 세 개가 생겨났습니다. 그 장면 자체가 가장 놀라웠습니다.

  • AI 에이전트는 ‘답’이 아니라 ‘결과물’을 만든다. 설명을 듣는 것과 실제 파일이 생기는 걸 보는 건 완전히 다른 경험이었습니다.
  • 도구마다 성격이 다르다. 같은 요청에도 누구는 차분하게, 누구는 드라마틱하게, 누구는 균형 있게 풀어냈습니다. 목적에 맞는 도구를 고르는 눈이 필요합니다.
  • 결과물의 ‘톤’도 확인해야 한다. 특히 AI 2027처럼 미래 시나리오를 다룰 때는, 멋진 디자인보다 현실과 가상을 정확히 구분하는 것이 더 중요하다고 느꼈습니다.
  • 결과물 이상의 배움. 웹페이지를 완성한 것뿐 아니라 GitHub, 로컬 작업, 클라우드 작업의 차이까지 직접 경험하며 이해하게 되었습니다.
한 줄 결론 AI 에이전트는 “대단하다더라”가 아니라 “직접 써보니 대단했다”로 바뀌었습니다. 그리고 그중 제게 가장 잘 맞는 동료는 Claude Code였습니다.
